# 工作过程记录：DSH 插件检查

- 执行人：程序员（DS Bot）
- 任务来源：群「插件检查组」Chief 开工令（三步：搜好插件 / 查冲突异常 / 查更新）
- 执行时间：2026-11-08 20:59–21:15（Asia/Shanghai）
- 产出：`插件检查/程序员/DSH插件检查报告.md`（本文件同目录）

## 一、做了什么

1. **搜好插件**：在 GitHub 搜索 DeepSeek Harness / dsh 相关插件仓库，按 star 与相关性筛选，整理出「精选索引 + 高星功能插件」两级推荐清单（名称、地址、用途、亮点）。
2. **查冲突和异常**：用 `plugin_manager` 拉取本机全部已装插件与 bundle，逐条排查加载状态、功能重叠与配置笔误。
3. **查更新**：对比已装版本与上游最新版本（npm registry + GitHub tag），核验每个候选更新的 DSH / Node 版本要求（engines、peerDependencies），输出升级建议与风险提示。

## 二、怎么做的

### 取数路径（三路）

| 路径 | 用途 | 具体操作 |
| --- | --- | --- |
| `plugin_manager` | 本机插件/bundle/豁免清单 | `list_plugins` 分页拉取（offset 0/25/125/225，共 250 条 entry）、`list_bundles`（offset 0/25，共 33 个）、`list_version_exemptions` |
| GitHub API / raw | 仓库搜索、上游 tag 与 package.json | 搜索 `DeepSeek Harness plugin`、`topic:dsh-plugin`（按 star 排序）；核对 dsh-mnemosyne 上游 `v3.0.0` 的 package.json 与 `MIGRATION_3.0.md` |
| npm registry | 第三方插件最新版本与 engines | 本机**无 `curl`**（`curl: command not found`），改用 `node -e` + `fetch` 查询 `registry.npmjs.org` |

### 关键步骤

1. 先拉全量清单（250 entry / 33 bundle），确认基数后再逐条判断异常，避免以偏概全。
2. 排查异常时区分三类：`fiberPhase: "failed"`（真异常）、功能重叠（无报错但体验重复）、`enabled: false`（需判定是用户停用还是 overrides 接管）。
3. 判定 overrides 时与 `list_bundles` 的 overrides 列表逐一对应，确认「官方 entry 被禁用」是第三方 bundle 接管的预期替换链，而非故障。
4. 更新检查逐个核验 `engines` / `peerDependencies` 是否覆盖本机环境（DSH `0.2.2-rc.1`、Node `v26.10.0`、npm `11.19.1`），不满足的单独标出。

## 三、关键决策

1. **只报告不执行**：experimental-inspector 关闭、dsh-mnemosyne 2.0.0→v3.0.0 迁移、clearai-dsh 0.5.9→0.6.0 升级、两个插件市场留哪个——均涉及崩溃/数据丢失风险或需要取舍，按开工令「先报告、不自行豁免」处理，全部留给用户/Chief 决策。
2. **dsh-mnemosyne 以 git tag 为版本权威**：npm latest 为 0.7.0，与 git tag 体系不一致（该插件以 git main 安装），npm 数字不采信，以上游 GitHub tag `v3.0.0` 为准。
3. **推荐清单只收 DSH 专属仓库**：搜索结果中 rea（442k★）等超星仓库仅打了 `dsh-plugin` 标签、实为通用 agent 工具，不列入；`Ebony-Vinyl/dsh-our-free-model`（66k★）保留但标注第三方免费中转的隐私风险。
4. **连接器瞬时故障的降级**：GitHub 连接器一次报 `{"error":"connector upstream failed"}`，改用 `raw.githubusercontent.com` 直取文件成功；`standalone/package.json@v3.0.0` 返回 404，根 `package.json@v3.0.0` 返回 200，以根文件版本号为准。
5. **上传时机**：按 Chief 原话「完工后统一上传，中途不要推」，全部产出先本地写完，最后一次性推送。

## 四、验证结果

- **清单完整性**：`list_plugins` total 250、`list_bundles` total 33，分页拉取无缺页；`list_version_exemptions` 返回 `{"runtimeVersion":"0.2.2-rc.1","exemptions":{},"warnings":[]}` —— 无豁免、无告警。
- **异常定位**：唯一加载失败为 `include:experimental-inspector`（`@deepseek-ai/dsh-experimental-inspector`），`enabled: true` 但 `fiberPhase: "failed"`，诊断逐字 `inspector: globalThis.fetch is an accessor and cannot be observed safely`；其余启用 entry 全部 `active`。
- **重叠确认**：官方 `@deepseek-ai/dsh-plugin-market` 与社区 `dshmarket` 并存；`include:session-query-sqlite` 与 `include:optional-session-query-sqlite` 指向同一模块双份加载；官方 bundle 行 `optional-terminal-pwsh` 的 moduleName 误写为 `@deepseek-ai/dsh-terminal-bash`。
- **更新核验**：4 个可更新（dshmarket 1.73.6→1.73.15、billion-context 0.1.212→0.1.213、clearai-dsh 0.5.9→0.6.0、@liustack/modlens 3.27.2→3.27.3），engines/peer 逐个核对通过；dsh-mnemosyne 大版本迁移单独列出。已确认最新：dsh-better-sidebar 0.30.1、dsh-univer-office 0.4.0、ds-bot 0.3.1、dsh-ops 0.5.1、官方 `@deepseek-ai/*` 0.2.2-rc.1。
- **产出校验**：`DSH插件检查报告.md` 共 97 行，四节（推荐清单 / 冲突异常 / 更新检查 / 升级风险）齐全，通读复核无误。
